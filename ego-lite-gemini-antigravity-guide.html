一、Ego Lite 是什麼？核心架構與優勢

Ego Lite（GitHub 專案 citrolabs/ego-lite，對應指令列工具為 ego-browser）是一套專為「人類與 AI Agent 協同作業」設計的開放原始碼 Chromium 瀏覽器環境。

與傳統在背景啟動乾淨無痕實例的自動化框架（例如 Playwright、Puppeteer）不同，Ego Lite 採用人機協作隔離工作區架構：

圖 1：Ego Lite（ego-browser）跨工具人機協作與 TaskSpace 隔離架構

與傳統瀏覽器自動化的核心差異

  1. TaskSpace 隔離且共用登入狀態：初次引導可匯入 Chrome／Edge／Brave 的 Cookie 與設定檔，Agent 可直接在您已登入的網站（例如內部系統、社群後台）運作；同時使用獨立的 TaskSpace 分頁工作區，不會搶佔您平常手動瀏覽的分頁與滑鼠焦點。
  2. 隨版本動態同步的 Skill 指南：執行 ego-browser skill 會印出與當前安裝版本完全對應的最新 API 規範，避免模型因記憶舊版用法而寫出過時程式碼。
  3. 原生人機接力（handOff）機制：當網站出現尚未登入、雙重驗證或安全檢查時，Agent 會停止自動操作並呼叫 task.handOff()，將分頁控制權安全交由人類手動處理完成後再接手續跑。
  4. 語意快照降低 Token 消耗：支援語意摘要與精準 DOM 操作，同時兼具視覺截圖與鍵鼠事件能力。

二、系統安裝與環境驗證（Windows ／ macOS）

使用 Ego Lite 前，需先安裝 Ego Lite 桌面應用程式（ego-browser 命令即由該應用程式提供）。

步驟 1：下載、安裝並完成首次 Onboarding

⚠️ 重要前置步驟

首次開啟 Ego Lite 應用程式後的「Onboarding 精靈」為必要步驟：ego-browser 指令必須在您於 GUI 完成 Onboarding 之後，才會自動註冊至系統 PATH。

Windows 平台

  1. Windows 目前無一鍵安裝 Shell 腳本，請直接前往官網 https://lite.ego.app/ 下載 Windows 安裝程式並執行。
  2. 若遇到 Windows SmartScreen 安全性警告視窗，點擊「其他資訊」→「仍要執行」。
  3. 啟動 Ego Lite 後完成畫面上的首次 Onboarding（可自由選擇是否匯入既有的 Chrome／Edge／Brave 設定檔）。
  4. 務必關閉並重新開啟一個新的終端機（既有終端機行程不會即時更新環境變數 PATH）。

macOS 平台

  • 手動安裝：從 https://lite.ego.app/ 下載對應架構的 DMG（Apple Silicon arm64 或 Intel x64）拖入 /Applications 後開啟完成 Onboarding。
  • 透過 Skill 腳本安裝：若已安裝 ego-browser Skill，於 Skill 目錄內執行以下腳本（會依 CPU 架構下載 DMG、安裝至 /Applications 或 ~/Applications、移除 Gatekeeper 隔離屬性並開啟 App；若首次開啟仍遭阻擋，至「系統設定 → 隱私權與安全性」手動允許執行即可）：
macOS Bash
sh skills/ego-browser/scripts/install.sh

步驟 2：管理設定檔匯入與版本升級

若首次設定後仍希望從其他瀏覽器匯入登入工作階段，可使用內建匯入工具（支援 chrome、edge、brave）：

設定檔匯入指令
# 查看所有可匯入的本機瀏覽器設定檔
ego-browser import list

# 匯入指定瀏覽器設定檔（支援 chrome、edge、brave）
ego-browser import --browser chrome --profile Default
ego-browser import --browser edge --profile Default
ego-browser import --browser brave --profile Default

日後升級至最新版 Ego Lite：

版本升級指令
ego-browser upgrade
💡 小提醒

每次執行 ego-browser upgrade 後，應重新執行一次 ego-browser skill 讓 AI 助理讀取新版 API 操作手冊。

步驟 3：驗證 ego-browser 執行環境

開啟新的終端機視窗後，依序執行下列檢查：

環境檢查指令（Windows PowerShell / cmd / macOS / Git Bash）
# 1. 確認指令路徑（依 Shell 擇一執行）
Get-Command ego-browser      # Windows PowerShell
where ego-browser            # Windows cmd
command -v ego-browser       # macOS / Git Bash

# 2. 查看主程式、Chromium 與內嵌 Node 版本
ego-browser --version

# 3. 驗證內嵌 Node 執行環境（PowerShell／cmd 無 heredoc，需使用 -e）
ego-browser nodejs -e "console.log('ego-browser ready')"

# （macOS / Linux / Git Bash 亦可使用 heredoc）
ego-browser nodejs <<'EOF'
console.log('ego-browser ready')
EOF

# 4. 確認可印出完整動態指南（尾端須見 "[ego-browser:skill] end of guide"）
ego-browser skill

若 ego-browser skill 在終端機輸出過長遭截斷，可先輸出至暫存檔再分段檢視：

PowerShell / Bash 匯出指南至暫存檔
# PowerShell
ego-browser skill > "$env:TEMP\ego-browser-skill.md"

# macOS / Bash
ego-browser skill > "$TMPDIR/ego-browser-skill.md"

三、先釐清：Gemini 網頁版 vs Gemini CLI vs Google Antigravity

許多使用者常混淆三種名稱相近的環境，能否結合 Ego Lite 取決於環境是否具備讀取本機 Skill 目錄與呼叫本機 Shell（ego-browser）的能力：

環境工具 能否使用 Ego Lite？ 原因與限制 全域 Skill 存放路徑 專案級 Skill 路徑
Gemini 網頁版
(gemini.google.com)		 ✕ 無法使用 純雲端沙盒服務，無法存取本機瀏覽器與 CLI。 不適用 不適用
Gemini CLI ✓ 完全支援 本機終端機 AI Agent，原生支援 Agent Skills 與 Shell 工具執行 ego-browser。 ~/.gemini/skills/ego-browser/ 或 ~/.agents/skills/ego-browser/ .gemini/skills/ego-browser/ 或 .agents/skills/ego-browser/
Google Antigravity ✓ 完全支援 本機 Agentic IDE／開發環境，透過 Customization System 漸進式載入全域與工作區 Skills。 ~/.gemini/config/skills/ego-browser/
(Windows: C:\Users\<使用者>\.gemini\config\skills\ego-browser\)		 .agents/skills/ego-browser/

Google Antigravity Skill 載入優先序（由高到低）

Antigravity 採用「漸進式揭露（Progressive Disclosure）」機制：平時僅注入各 Skill 的 name 與 description，當判斷任務需要操作瀏覽器時才完整讀取 SKILL.md。當多個位置同時存在同名 Skill 時，覆蓋順序如下：

  1. Workspace Project：由當前工作目錄往上掃描至版本庫根目錄的 .agents/skills/
  2. Declared Configurations：工作區 skills.json 或 plugins.json 明確宣告之項目
  3. Global Discovery：~/.gemini/config/
  4. Built-in Customizations：應用程式內建 Skills
  5. Global Declared Configurations：全域 JSON 設定檔宣告項目

四、在 Gemini CLI 與 Antigravity 安裝 ego-browser Skill（一次設定，全域通用）

安裝完桌面應用程式後，還需將 ego-browser Skill（包含 SKILL.md、references/、scripts/ 等檔案）放進 AI 助理的探索目錄，讓任何新舊專案都能隨時調用。

方法 A：透過官方 skills CLI 一鍵安裝

CLI 安裝指令
npx skills add citrolabs/ego-lite

# 或直接指定儲存庫內的 ego-browser 子目錄
npx skills add github:CitroLabs/ego-lite/skills/ego-browser

方法 B：直接請 AI Agent 自動安裝

開啟 Gemini CLI 或 Antigravity 後，貼上以下指令交由助理安裝與驗證：

「請幫我安裝 citrolabs/ego-lite 的 ego-browser Skill 到全域 Skill 目錄，讓我在 Gemini CLI 與 Antigravity 的所有專案都能隨時調用，並驗證 ego-browser 環境。」

方法 C：確保「黃金雙全域路徑」同步就緒

若希望在同一台電腦上無論啟動 Gemini CLI 還是 Google Antigravity（任意專案資料夾）都能免設定直接使用，請確認以下兩個全域資料夾皆完整包含 ego-browser（內有 SKILL.md、references/、scripts/ 等子目錄）：

  1. ~/.agents/skills/ego-browser/（跨工具共享標準路徑，Gemini CLI 原生探索）
  2. ~/.gemini/config/skills/ego-browser/（Google Antigravity 全域探索路徑）
Windows PowerShell 同步腳本
$src = "$HOME\.agents\skills\ego-browser"
$dst = "$HOME\.gemini\config\skills\ego-browser"
New-Item -ItemType Directory -Force -Path (Split-Path $dst) | Out-Null
Copy-Item -Path $src -Destination $dst -Recurse -Force
macOS / Linux 建立符號連結
mkdir -p ~/.gemini/config/skills
ln -sfn ~/.agents/skills/ego-browser ~/.gemini/config/skills/ego-browser

Gemini CLI 內建驗證指令

Gemini CLI 互動指令
/skills list
/skills reload
/skills link ~/.gemini/config/skills/ego-browser --scope user
🖥️ 本機環境現狀確認

目前這台 Windows 主機的雙全域目錄已就緒（C:\Users\USER\.gemini\config\skills\ego-browser\SKILL.md 與 C:\Users\USER\.agents\skills\ego-browser\SKILL.md 皆為 v2.2.1，系統 PATH 上的 ego-browser 為 0.6.3.17）。

五、日常使用指南：在 Gemini CLI 與 Antigravity 實戰調用

1. 自然語言觸發方式與實用 Prompt 範例

由於 ego-browser Skill 的 description 已明確設定為預設瀏覽器工具，您在 Gemini CLI 或 Antigravity 中只需要明確提到網站任務或指名 ego-browser，助理就會先執行 ego-browser skill 確認最新指令集後開始作業。

範例 1（需登入權限的網站資料整理）：「用 ego-browser 開啟 https://www.facebook.com/profile.php?id=...，協助收集指定主題的貼文與留言內容並彙整成一份離線網頁。」

範例 2（本機／線上 Web App 實機 QA 測試）：「用 ego-browser 開啟 http://localhost:3000，以我目前的登入身分測試表單送出與清單篩選功能，若有 Console 錯誤或版面破版請截圖並修正。」

範例 3（建立可重複增量更新的資料管線）：「幫我在專案內用 ego-browser nodejs 寫一個增量同步腳本，只抓取最新貼文並更新 index.html，遇到未登入時自動暫停交給我接手。」

2. 核心工作流與 TaskSpace 生命週期（重要！）

⚠️ API 關鍵差異：ego-browser 不是 Playwright！

ego-browser 僅公開自家精簡 API（TaskSpace、Page、FileChooser、mouse、keyboard、page.evaluate()、page.cdp()）。撰寫或審查腳本時，不可使用未定義的 Playwright 方法如 locator()、getByRole()、context()、expect()、route()；凡內建 API 未涵蓋的 DOM 邏輯，統一改用 page.evaluate() 執行。

階段一：啟動或復原 TaskSpace（每次回覆沿用同一個任務空間）

JavaScript · 啟動或取回工作空間
// 先查詢目前存在的空間，依所有權狀態決定建立、取回或接管
const existingSpaces = await listTaskSpaces();
const prev = existingSpaces.find((s) => s.name === "my-research-task");

const task = !prev
  ? await taskSpace("my-research-task")
  : prev.ownership === "user"
    ? await claimTaskSpace(prev.id)
    : prev.ownership === "agentDelegatedToUser"
      ? await takeOverTaskSpace(prev.id)
      : await taskSpace(prev.id);

const page = (await task.pages())[0] ?? (await task.adopt((await task.tabs())[0].page));
await page.goto("https://example.com", { timeout: 28_000 });

階段二：遇到登入牆／驗證時的人機接力（handOff）

當偵測到登入畫面或安全驗證時，千萬不要嘗試繞過或自動破解驗證，也不要呼叫 finish()；待使用者確認完成手動操作後，下一輪再透過 await takeOverTaskSpace(spaceId) 接回同一個空間：

JavaScript · 人機接力手交控制權
const needLogin = await page.evaluate(() =>
  /\/login|\/checkpoint/.test(location.pathname) ||
  Boolean(document.querySelector('input[type="password"]'))
);

if (needLogin) {
  await task.handOff(); // 將控制權交給使用者於 Ego Lite GUI 手動完成
  console.log(JSON.stringify({ status: "handed_off", spaceId: task.spaceId }));
  process.exit(0);
}

階段三：全部任務完成後，在獨立腳本關閉空間（finish）

根據 ego-browser skill 規範，任務確定全部完成、需要清理工作區時，應在最後獨立執行的腳本中呼叫 finish()，且呼叫後不可再操作任何 Page：

JavaScript · finish-space.mjs 收尾清理
// finish-space.mjs（於主要資料抓取腳本執行結束後另行呼叫）
const spaces = await listTaskSpaces();
const target = spaces.find((s) => s.name === "my-research-task");
if (target && target.ownership !== "agentDelegatedToUser") {
  const task =
    target.ownership === "user"
      ? await claimTaskSpace(target.id)
      : await taskSpace(target.id);
  await task.finish({ keep: [] });
}

六、實戰避坑指南與疑難排解（含 Windows PowerShell 實測經驗）

1. Windows PowerShell 5.1 語法與字元編碼陷阱

  • 沒有 Bash heredoc (<<'EOF')：PowerShell 5.1 不支援 <<'EOF'，直接照抄 Unix 範例會出現語法錯誤。
  • 外部程式吃雙引號／管線亂碼：使用 ego-browser nodejs -e "..." 在 PowerShell 夾帶複雜引號或繁體中文字串時，容易被參數解析或系統字碼頁損毀。
  • 最佳解法：一律先將腳本寫成 UTF-8 編碼的 .mjs 檔案，再使用 import() 匯入執行，或透過 Node spawnSync("ego-browser", [...], { shell: false }) 呼叫：
PowerShell 推薦執行方式
ego-browser nodejs -e "await import('file:///C:/path/to/your-script.mjs')"

2. 環境變數與工作目錄隔離特性

ego-browser nodejs 內嵌執行期不會完整繼承外層 Shell 的自訂 process.env 或當前工作目錄（CWD）。路徑統一使用 import.meta.url（搭配 fileURLToPath + dirname + resolve）定位專案根目錄；執行期參數寫入專案 JSON 設定檔讓腳本讀取。

3. 清理 Cookie／快取與儲存空間的風險警告

執行涉及清除 Cookie、快取或 LocalStorage 的指令前，務必先閱讀 Skill 內附的 references/clearing-state.md；因為部分清除 API 的作用範圍會觸及整個共用的 Ego Lite 瀏覽器設定檔，可能意外登出您在其他網站的日常工作階段。

4. 常見錯誤快速排除對照表
