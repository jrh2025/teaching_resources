一、系統概述與核心價值

ClassNet Sentinel（班級網盾）v2.4.0 是一套專為現代智慧校園與數位教學環境量身打造的 Wi-Fi 網路掃描、在線設備監控、主動資安防禦與課堂秩序控制系統。

在教育數位轉型政策下，「班班有大屏、生生用平板」已成為各級學校教學常態。然而，開放且普及的教室 Wi-Fi 環境隨之帶來了前所未有的管理挑戰：

  1. 分心失控：學生在課堂私自開啟非授權社群平台、影片或偷玩線上遊戲。
  2. 頻寬遭竊：鄰近班級、校外人士未經許可「盜連、蹭網」，癱瘓珍貴教學頻寬。
  3. 身分隱匿：學生自帶設備（BYOD）使用「隨機 MAC（私密 Wi-Fi 位址）」，導致傳統網管工具無法辨識目標。
  4. 校園資安威脅：學生若私自安裝駭客工具、私接家用無線分享器，或有心人士架設未經許可之網路攝影機，將嚴重威脅師生隱私。
  5. 控制權失衡：傳統校園網管工具繁複冗長，授課教師在課堂上「看得到卻管不到」，無法即時處置。

ClassNet Sentinel v2.4.0 透過現代化輕量主控台與教師隨身行動端，賦予現場授課教師最直覺、最精準的網路掌控力。它不僅讓網路狀態「100% 透明可視」，更能讓教師在發現異常時「立即出手控制」，真正實現數位科技輔助教學的秩序平衡。

二、產品設計理念 (Design Philosophy)

ClassNet Sentinel 的核心設計根植於「以教學現場為核心，將網管主控權還給教師」的理念。

2.1 教育現場痛點與時代挑戰

  • 痛點一：傳統網管軟體過度複雜
    現有專業網管軟體（如 Wireshark、PRTG、Cisco Dashboard）專為網路工程師設計，介面充滿封包協定代碼與十六進位資料，非資訊專業的授課老師難以上手。
  • 痛點二：發現問題卻無能為力
    市售大部分 WiFi 掃描器僅具備「被動顯示」功能，即便老師看到陌生裝置偷連或學生分心，也無法立即切斷連線，必須打電話請學校資訊組進後台黑名單封鎖，緩不濟急。
  • 痛點三：模擬假資料失去實戰價值
    許多工具為求展示華麗，充斥預設的虛擬假設備，無法在真正的區域網路中探測到剛開機的手機與設備。
  • 痛點四：教師受限於講桌無法隨身走動
    老師若必須坐在電腦前才能操作，便失去了巡堂互動的教學機動性。

2.2 四大核心設計哲學

核心設計哲學 具體實現手段 教學現場效益
1. 零門檻・無痛部署 單一獨立免安裝執行檔 (Single EXE)，無外部資料庫依賴 雙擊即開即用，免請資訊組安裝環境，隨身隨插隨用
2. 主動防禦・精準控制 一鍵斷網、自動封鎖陌生載具、全班一鍵專注模式 告別無力感，發現分心秒級處置，教學節奏完全掌控
3. 100% 真實資料原則 實體 RAW Socket ARP / ICMP 原生探測，嚴禁虛擬資料 反映教室物理真實，隨機 MAC 智慧歸納，無誤導資訊
4. 雙端協同・教師自主 講桌大螢幕主控台 + 教師隨身手機行動端 (APK / PWA) 老師自由在教室穿梭巡堂，口袋手機隨時一鍵控制

1. 零門檻・無痛部署 (Zero Configuration & Portability)

學校公務電腦通常具備嚴格的權限管制與軟體限制。ClassNet Sentinel 採用單一獨立免安裝執行檔（Single Portable EXE） 架構，雙擊即可啟動後台服務與現代化網頁儀表板，無須額外架設 Python、Node.js 或安裝繁雜的資料庫系統，隨插即用。

2. 從「旁觀」到「控制」的主動防禦 (Active Containment)

不同於傳統掃描器「只看不動」，ClassNet Sentinel 核心價值在於具備主動防禦手段： - 一鍵封鎖裝置 (Block Internet)：立即將目標切斷於區網之外。 - 新裝置自動封鎖 (Autoblock)：白名單外的陌生新設備一連上即被系統第一時間自動阻斷。 - 課堂專注模式 (Focus Mode)：老師講解時一鍵切斷全班學生平板，解除講解後一秒恢復。

3. 100% 真實數據原則・拒絕虛擬模擬 (Zero Simulation)

本系統所有偵測到的 IP、MAC、製造商 OUI、活躍通訊埠、網路延遲與封包遺失率，均來自 Windows 原生系統 API、ARP 緩存矩陣與真實 TCP/ICMP 封包探測。系統內部絕不插入預設假設備，讓教師看到的每一個訊號皆反映當下教室的物理真實。

4. 雙端協同・以教師為中心的操控體驗 (Teacher-Centric Dual Control)

結合講桌大螢幕主控台與教師隨身行動端 (手機/平板)： - 桌面端提供宏觀視野：長期網速趨勢、全盤設備分類、路由弱點矩陣、專業網管診斷。 - 行動端提供極速巡堂：教師拿著手機巡堂時，只要點一下即可精準封鎖分心學生的平板。

三、核心技術深度解析：網路阻斷原理與系統影響評估

3.1 本軟體使用何種技術阻斷設備網路？

ClassNet Sentinel 採用工業級的 「雙模動態路由阻斷技術（Dual-Mode Dynamic Containment Engine）」，依據系統底層驅動環境自動啟用最佳防禦架構：

flowchart TD
    A["教師觸發【一鍵斷網】/【專注模式】"] --> B{"系統底層驅動環境檢測"}
    B -- "已安裝 Npcap 原生驅動 (推薦)" --> C["核心 L2 阻斷：雙向 ARP 閘道重定向<br>(ARP Gateway Redirection)"]
    B -- "未安裝驅動 (標準相容環境)" --> D["相容 L4 阻斷：主動 TCP Reset 封包注入<br>(Active TCP RST Injection)"]
    C --> E["目標設備 ARP 快取被導向無效黑洞<br>無法尋獲路由器真實 MAC"]
    D --> E2["目標設備建立連線瞬間遭 RST 重置<br>所有 Web / 應用連線即時中斷"]
    E --> F["設備完全失去網際網路存取能力<br>(封鎖生效)"]
    E2 --> F

1. 核心 L2 阻斷技術：雙向 ARP 閘道重定向 (ARP Gateway Redirection)

  • 技術原理：
    在乙太網與 Wi-Fi（IEEE 802.11）區域網路中，設備要對外上網，必須透過 位址解析協定（ARP, Address Resolution Protocol） 查詢預設閘道（如 192.168.1.1）的實體 MAC 位址。
    當教師在主控台對目標學生載具（如 192.168.1.50）啟用「一鍵斷網」時，系統透過 Npcap 驅動程式 發送精準建構的 ARP 應答訊框，告訴目標載具「閘道的 MAC 是無效位址（或本機虛擬介面）」。
  • 阻斷效果：
    目標設備所發出的所有網頁請求、影音串流封包，均會被傳送至無效黑洞，完全無法到達真正的 Wi-Fi 路由器，達成秒級、100% 徹底的連線阻斷。

2. 相容 L4 阻斷技術：主動 TCP RST 封包注入 (Active TCP Reset Injection)

  • 若教師電腦尚未安裝 Npcap 驅動，系統自動切換至無驅動相容防禦模組。系統監聽目標 IP 之 TCP 握手交握，主動向目標設備注入 RST（連線重置）訊號，使其瀏覽器頁面無法完成載入。

3.2 該技術對軟體、硬體與作業系統是否有不良影響？

許多教師與網管人員非常關心：「這樣強制切斷學生設備的網路，會不會搞壞學生的平板？會不會弄壞教室的分享器？」
答案非常明確：100% 絕對安全！對任何硬體設備、作業系統與應用軟體皆無任何不良影響。

檢驗維度 客觀安全性評估 技術實現與影響說明
1. 實體硬體層 🟢 100% 零損傷 純封包收發，無電壓/射頻修改，無快閃記憶體額外寫入，電池與零件壽命零折損。
2. 作業系統核心層 🟢 完全無痕 運作於暫態記憶體快取 (RAM)，無核心檔案竄改、無登錄檔修改、無病毒後門。
3. 應用程式層 🟢 零資料破壞 僅呈現常規網路逾時 (Timeout)，程式完全不會崩潰或檔案損壞。
4. 復原機制 🟢 秒級還原 點擊恢復上網後，發送正向真實廣播，1~2 秒內無痛無痕自動復原。

1. 對硬體層面（零磨損、零損傷）

  • 本系統僅在無線空氣訊號與實體網卡間進行標準網路協定封包的收發。
  • 不涉及任何硬體過載、電壓調整、頻率修改或射頻晶片超頻。
  • 不涉及快閃記憶體（Flash / SSD）的額外抹寫，對手機、平板、電腦的電池壽命與電子零件完全零耗損。

2. 對軟體與作業系統層面（完全無痕、非入侵）

  • 不修改系統檔案：ARP 協定本質上運作於作業系統的暫態記憶體快取（RAM-based ARP Cache）中，重開機或快取過期即自動消失。
  • 無後門、無植入：受控設備不需要安裝任何客戶端程式（Clientless Agentless），學生設備完全不需要越獄（Jailbreak）或取得 Root 權限。
  • 使用者體驗：在學生端看來，其感受僅等同於「教室 Wi-Fi 暫時收不到外網訊號」或「網頁連線逾時」，不會引發系統崩潰（藍屏當機）或資料毀損。

3.3 阻斷解除與恢復機制 (Symmetric Cache Restoration)

當教師點擊 【恢復上網】、取消專注模式，或直接關閉 ClassNet Sentinel 程式時：

  1. 主動正向修復廣播：系統的守護進程會立即向目標設備及路由器雙向發送「正向標準真實 ARP 宣告（Gratuitous ARP）」，主動將真正的路由器 MAC 位址寫回目標設備的記憶體快取。
  2. 無痕秒級還原：目標設備的路由路徑在 0.5~2 秒內完全校正歸位，學生平板立刻無縫恢復上網，無需重新連線 Wi-Fi，亦無需重新開機。

四、系統身分安全防護機制：教師 PIN 碼與防未授權操控

4.1 為什麼需要身分驗證？防範陌生人與學生越權操控

ClassNet Sentinel 具備跨設備協同能力（手機可遠端控制講桌主機）。然而，這也引發了一個關鍵的資安風險：

「如果有調皮的學生用手機連上教室 Wi-Fi，在瀏覽器輸入老師電腦的 IP（例如 http://192.168.1.116:8000），是否也能進入主控台把全班甚至老師的電腦斷網？」

答案是：絕對不可能！
ClassNet Sentinel v2.4.0 導入了銀行等級的 「雙軌多因子身分防禦體系（Two-Track Security Guard）」，將講桌實體主機與 Wi-Fi 外部連線嚴格隔離。

4.2 本機免密特許與外網嚴格鎖定機制 (Localhost Exemption)

系統自動辨識連線請求的來源網路身分：

flowchart TD
    Req["存取請求到達系統 API / 網頁"] --> Check{"連線來源 IP 判定"}
    Check -- "來自本機 (127.0.0.1 / localhost)" --> Local["講桌本機電腦 (實體教師在場特許)"]
    Check -- "來自區域網路 (192.168.x.x)" --> Ext["外部 Wi-Fi 設備 (學生載具 / 訪客)"]
    Local --> Allow1["自動直接放行<br>教師無需繁瑣輸入密碼"]
    Ext --> TokenCheck{"是否持有合法 X-Admin-Token？"}
    TokenCheck -- "已通過 PIN 驗證" --> Allow2["放行存取控制 API"]
    TokenCheck -- "未認證 / 密碼錯誤" --> Deny["阻斷並回應 403 Forbidden<br>記錄資安警告日誌"]
  1. 講桌本機電腦（實體在場免密特許，Localhost Exemption）：
    當教師坐在講台電腦前操作本機儀表板時，連線 IP 為 127.0.0.1 / localhost。系統判定教師具有物理實體存取權，自動給予完全信任與綠色特許，老師每次開機上課無須繁瑣重複輸入密碼，直接秒開即用。
  2. 外部 Wi-Fi 行動設備（嚴格 PIN 碼遮罩鎖定）：
    任何透過無線網路連入的設備（例如 192.168.1.100 的學生手機或筆電），一律強制阻擋於主介面之外，彈出全螢幕 PIN 碼解鎖遮罩，且遮蔽所有後端數據。未通過驗證前，畫面無法點擊、無法瀏覽設備清單。

4.3 後端 API 資安守門員：非授權設備 403 Forbidden 攔截與日誌稽核

有些具備資訊專長或好奇心強的學生，可能會嘗試不透過瀏覽器網頁，而是利用終端機命令（curl、Postman 或 Python 腳本）直接向後端 API（如 POST /api/block、POST /api/unblock）發送偽造控制請求。

ClassNet Sentinel 在後端 FastAPI 微核心上架設了 全域資安守門依賴項 verify_admin_access()： - 凡是沒有攜帶合法密鑰 Token（X-Admin-Token）的外部請求，後端伺服器在執行任何業務邏輯前，直接以 403 Forbidden 徹底斬斷。 - 自動觸發資安警告日誌：系統立即向 timeline_events 資料庫寫入警告事件：
[UNAUTHORIZED_ACCESS_BLOCKED] 資安攔截：來自 192.168.1.103 嘗試未授權呼叫 POST /api/unblock，已被系統阻斷！ - 老師在講桌主控台的【事件時間軸】上，可以清清楚楚抓出是哪一台設備在課堂上嘗試駭入或擅自操作系統！

4.4 教師管理 PIN 碼登入、修改與手動鎖定指南

  • 預設教師 PIN 碼：系統初始出廠管理密碼為 8888。
  • 教師手機初次解鎖：
    老師拿手機連上教室 Wi-Fi 掃碼開啟網頁後，畫面將呈現精美的暗黑鎖定介面。輸入 8888 並點擊【解鎖主控台】，系統驗證成功後將核發加密 Token 並存入手機，接下來 7 天內在該教室 Wi-Fi 均享有無感操控。
  • 變更教師專屬 PIN 碼：
    1. 在主控台頂部導覽列，點擊安全狀態旁的 「🔑 鑰匙圖示」。 2. 彈出【變更教師管理 PIN 碼】視窗。 3. 輸入新密碼（至少 4 位數字或英數字，例如 5678 或 teach99）並再次確認。 4. 點擊【確認變更】，新密碼立即生效，舊 Token 全部作廢。
  • 手動鎖定主控台：
    當老師準備離開教室、下課或暫時走開時，可點擊頂部 「🔒 鎖定圖示」，系統立即進入鎖定遮罩狀態，防止他人趁隙操作。

五、課堂惡意干擾防治專章：防堵學生私自安裝同類軟體

5.1 學生在課堂安裝同類軟體（如 NetCut）的潛在威脅

在資訊課堂或高年級教學現場，常有少數對網路技術好奇或調皮的學生，嘗試在自己的筆電、手機甚至教室電腦上安裝 NetCut（網路剪刀手）或同類 ARP 阻斷軟體，惡作劇切斷同學的連線，甚至嘗試切斷老師的講桌電腦。
面對這種情況，單靠教師一人肉眼很難即時抓出幕後黑手。學校與教師應採取以下 「四層縱深防禦體系（Defense-in-Depth）」 徹底杜絕：

防護層級 部署位置 關鍵防禦機制 抵禦成效
第一道防線 應用軟體層 ClassNet Sentinel 內建廣播異常動態監控 即時警報可疑主機，支援一鍵反制斷網
第二道防線 無線基地台 (AP) 開啟 AP 隔離 (Client Isolation) 徹底阻斷學生端橫向訊框，攻擊封包硬體直接拋棄
第三道防線 校園骨幹交換器 動態 ARP 檢測 (DAI) 與 DHCP Snooping 交換器埠口硬體級防護，偽造 ARP 直接阻斷
第四道防線 學生載具與終端 學生標準權限 + MDM 白名單與除錯鎖定 無管理員權限無法安裝驅動，工具根本打不開

5.2 第一道防線：ClassNet Sentinel 內建廣播異常動態監控

  • 異常廣播探針：
    ClassNet Sentinel 的守護線程隨時監聽教室網段內的 ARP 與 DHCP 流量。如果有任何非閘道設備開始大量廣播偽造的 ARP 應答，系統會立即捕捉該訊框的來源 MAC 與 IP。
  • 主控台即時警報：
    系統會在【事件時間軸】與頂部警示列立即彈出高危警告，標註「⚠️ 偵測到可疑主機 (IP: 192.168.1.120) 正在發送異常網路廣播！」，老師可直接對該 IP 執行【一鍵斷網】，使其軟體立即失效！

5.3 第二道防線：教室 Wi-Fi AP 隔離 (Client Isolation) —— 最根本無敵的防禦

這是防範校園區網 ARP 攻擊最有效、最根本、一勞永逸的黃金法則： - 原理：
在教室的無線基地台（Wi-Fi AP）或路由器後台管理介面中，開啟 「AP 隔離（Client Isolation / AP Isolation / Station Separation）」 功能。 - 防禦成效：
開啟後，所有連入 Wi-Fi 的學生平板與手機彼此之間被強制隔絕，只能單向連向外部網際網路，完全無法在無線網路內互相傳遞資料訊框。 - 結果：學生就算在其手機或平板上開啟 NetCut，其發出的 ARP 攻擊封包會直接在 AP 內部被硬體晶片丟棄，根本無法送達任何其他同學或老師的電腦，攻擊能力瞬間歸零！

5.4 第三道防線：校園交換器動態 ARP 檢測 (DAI) 與 DHCP Snooping

若教室電腦採用實體網路線（乙太網路 RJ-45）連接至校園骨幹交換器，學校資訊組可於網管型交換器（Managed Switch）啟用以下兩項企業級安全功能： 1. DHCP Snooping：交換器僅允許合法機房的 DHCP 伺服器發放 IP，並自動建立 IP 與 MAC 綁定信任表。 2. 動態 ARP 檢測 (Dynamic ARP Inspection, DAI)：交換器比對每一個經過埠口的 ARP 封包，若發現學生電腦宣稱自己是預設閘道，交換器在硬體線路上直接阻斷該埠口，學生軟體完全無計可施。

5.5 第四道防線：學生載具 MDM 鎖定與電腦權限控管

從載具終端徹底防範未經授權的軟體安裝： 1. 公用教室電腦帳號權限：
學生上機使用的 Windows 帳號必須設定為「標準使用者（Standard User）」，嚴禁給予 Administrator 本機系統管理員權限。
* 關鍵要點：NetCut 等底層網路工具運行時，必須安裝 WinPcap / Npcap 驅動程式並取得管理員特權。沒有管理員權限的學生帳號，完全無法安裝驅動，軟體根本打不開！ 2. 教育部生生用平板 (MDM 控管)：
學校配發的 iPad 或 Android 平板均納入教育局行動載具管理系統（MDM，如 Jamf、Google Workspace for Education）。
* 啟用 App 安裝白名單，阻擋非教學 App 的安裝。 * 關閉「開發者除錯模式（Developer Options）」，防止學生自行側載（Sideloading）APK 攻擊工具。

六、功能全覽與操作指南 (Feature Walkthrough)

6.1 即時設備掃描與智慧識別 (Real-time Scanner & Host Tracking)

操作路徑：主畫面頂部 ➔ 點擊【真實掃描】按鈕

  1. 一鍵全網探測：
    點擊後，系統會於 1~2 秒內向整條教室網段發出喚醒探測，並自動解析線上設備之真實 IP、實體 MAC、網卡製造商（如 Apple, Samsung, Google, Intel, TP-Link）。
  2. 智慧分類標籤體系： - 🏫 導師機：教師本機電腦及已認領的教師手機，永遠置頂並享有免斷網白名單特權。 - 🌐 網路閘道/分享器：教室核心路由器（通常為 192.168.1.1）。 - 📱 智慧手機/平板：包含隨機私密 MAC 之行動裝置。 - 💻 學生平板：學校配發之教學載具。 - ⛔ 可疑黑名單：被系統或手動封鎖的上網設備。
  3. 全景連線觀測面板 (Device Inspector)：
    點選任何一台在線設備，即可彈出完整連線觀測卡片： - 檢視實體 MAC、製造商、連線介面（如 Wi-Fi 802.11 / 乙太網路）。 - 查看該設備目前開放的網路服務（如 AirPlay 投影、Web 伺服器等）。 - 檢視今日上網時限配額與剩餘時間。 - 查閱該設備專屬的上下線與封鎖時間軸歷史紀錄。

6.2 課堂主動防禦與自動封鎖 (Active Defense & Autoblock)

操作路徑：主畫面頂部功能列 ➔ 切換【新裝置自動封鎖】開關

  • 手動一鍵斷網：
    在設備列表或詳情面板中，點擊紅色的 【一鍵切斷上網】 按鈕，系統會立即切斷該設備對外存取網際網路的權限；再次點擊 【恢復上網】 即可秒級還原。
  • 新裝置自動封鎖 (Autoblock)：
    在開關切換為啟用狀態後，凡是有未曾登錄過的新裝置嘗試連入教室 Wi-Fi，系統會在第一時間自動將其阻斷上網並發出警報，徹底防範鄰班學生或路人蹭網。

6.3 課堂專注模式 (Focus Mode 一鍵全體學生載具斷網)

操作路徑：主畫面頂部工具列 ➔ 點擊【全班專注模式 (學生斷網)】按鈕

  • 使用時機：老師在講台上進行重要觀念解說、黑板板書、全班收心或課堂隨堂考時。
  • 運作機制：
    點擊後，按鈕轉為紅色閃爍之「專注模式執行中」。系統會自動對所有標記為【學生平板】的設備執行一鍵切斷網路，而【導師機】與【網路閘道】則完全不受影響。
  • 一秒恢復：老師講解完畢需要學生操作平板時，再次點擊按鈕，全班平板立即恢復上網能力。

6.4 教師時限管控與定時斷網排程 (Time Limit & Scheduling)

操作路徑：設備列表 ➔ 點選目標設備的【時限】按鈕

  1. 每日上網額度限制 (Time Quota)：
    - 可設定該載具每日允許上網的分鐘數（例如每節課自主學習 45 分鐘）。 - 系統會以秒級為單位精密計算該設備的實際活躍時間。當額度用盡時，系統自動將其切斷上網，並在備註註記「今日上網配額已用盡」。 - 面板提供 【+15分鐘】、【+30分鐘】 快捷加時按鈕，以及一鍵重置計時按鈕。
  2. 定時斷網排程 (Schedule Block)：
    - 勾選「啟用定時斷網」，設定開始時間（如 12:00）與結束時間（如 13:15）。 - 在指定的時間區間內（如午休時間或特定自習節次），系統會自動精準執行斷網；時間結束後自動無感恢復連線。

6.5 教室核心路由器安全弱點檢查 (Gateway Vulnerability Check)

操作路徑：切換至【安全漏洞掃描】標籤頁 ➔ 點擊【立即檢查】

針對教室網路的核心生命線 —— 預設閘道 (Default Gateway, 通常為 192.168.1.1) 進行深度的資安通訊埠清查，具備旋轉探測動態反饋、百分制安全評分卡與 9 大關鍵通訊埠清查矩陣：

通訊埠 (Port) 服務名稱 風險等級 說明與加固建議
Port 23 Telnet 🔴 極高危 明文遠端傳輸協定，密碼容易遭側錄。強烈建議關閉！
Port 7547 TR-069 🔴 極高危 電信商遠端管理後門，歷年多起重大勒索病毒入侵途徑。
Port 21 FTP 🟠 中高危 未加密檔案傳輸，易遭受暴力破解與勒索軟體攻擊。
Port 3389 RDP 🟠 中危 Windows 遠端桌面，若暴露在外網容易招致自動化暴力破解。
Port 22 SSH 🟡 提示 安全加密遠端管理通訊埠，若僅在內網維護使用則屬安全。
Port 53 DNS 🟢 正常 路由器本機網域名稱解析轉發服務，區網正常教學必備。
Port 80 HTTP 🟡 提醒 路由器未加密 Web 管理介面，建議切換為 HTTPS 登入。
Port 443 HTTPS 🟢 安全 現代路由器標準加密管理介面，連線安全無虞。
Port 8080 Web Proxy 🟡 提醒 備用 Web 管理介面或代理伺服器通訊埠。

6.6 課堂隱私與針孔攝影機偵測雷達 (Hidden Camera Radar)

操作路徑：切換至【安全漏洞掃描】標籤頁 ➔ 點擊【即時偵測】

專為校園教室、更衣室、會議室或戶外教學住宿環境設計： - 深度探測 RTSP (Port 554)：偵測是否有各型 IP 網路攝影機正在傳送即時影像串流。 - 探測 ONVIF (Port 3702/8000)：偵測網路攝影機標準通用廣播協定。 - 可疑攝影機高亮警報：一旦發現疑似針孔或連線攝影機，立即在列表中標註 📷 警示圖示並發出資安警告，全力守護師生隱私。

6.7 專業網管診斷工具箱

操作路徑：切換至【專業網管工具】標籤頁

  1. LAN 喚醒 (Wake on LAN, WoL)：輸入教室公務電腦或大屏之 MAC 位址，發送標準魔術封包（Magic Packet），直接透過網路遠端開機。
  2. 私接 Rogue DHCP 分享器探測：探測教室內是否有學生或老師私自插上未報備的家用無線分享器，防止配發錯誤 IP 導致全班斷網。
  3. 原生 ICMP Ping 延遲診斷：調用系統原生底層 Socket 發送 4 次探測，精密測量往返時間（Min / Avg / Max）與封包遺失率。
  4. Traceroute 路由節點追蹤：追蹤封包到達網際網路（如 8.8.8.8）途經的每一跳節點與各跳延遲，快速排查是學校機房斷線還是電信商線路故障。

6.8 完整事件時間軸與動態稽核 (Full Event Audit Timeline)

操作路徑：切換至【事件時間軸】標籤頁

系統完整記錄教室網路中的所有歷史動態： - 裝置首次發現：記錄某台新手機在幾點幾分首次連線。 - 自動防禦處置：記錄哪一台設備因為未經授權而被系統切斷網路。 - 資安攻擊攔截：記錄哪個外部 IP 嘗試非法呼叫 API 或輸入錯誤 PIN 碼。 - 教師手動操作：記錄老師手動啟動專注模式、調整時限、認領手機等事件。

七、教師行動端安裝與配對指南

ClassNet Sentinel v2.4.0 提供 三種使用管道，滿足不同老師的偏好與操作習慣：

行動端途徑 部署方式 適用載具 核心優勢
途徑一：免安裝 Web App 掃碼加入主畫面 (PWA) iOS (Safari) / Android (Chrome) 0 秒即開即用，免安裝任何 APK，跨平台通用 (最推薦)
途徑二：/pair 安全認領 瀏覽器開啟 /pair + PIN 碼 智慧型手機 / 平板電腦 一鍵自動登記升級為【導師機】，享有永久免斷網白名單
途徑三：原生 APK 直裝版 下載安裝獨立 .apk 包 Android 7.0 以上手機 / 平板 獨立桌面圖示，斷線自動重連，支援手動指定主機 IP

7.1 方式一：免安裝 Web App (PWA 模式) —— 最推薦、零門檻

  1. 教師手機連上與教室電腦相同的 Wi-Fi 網路。
  2. 在電腦主控台右上角點擊 「📱 教師手機 App」 按鈕，螢幕將彈出專屬連線 QR Code。
  3. 打開手機相機掃描 QR Code（或在手機瀏覽器輸入 http://教師電腦IP:8000）。
  4. 輸入教師管理 PIN 碼（預設 8888）完成驗證解鎖。
  5. 將網頁加入手機主畫面： - iPhone (Safari)：點擊底部分享圖示 ➔ 選擇 「加入主畫面」。 - Android (Chrome)：點擊右上角「⋮」選單 ➔ 選擇 「加到主螢幕」 或 「安裝應用程式」。
  6. 手機桌面上即會生成專屬的「ClassNet 班級網盾」圖示，點開即可全螢幕獨立運行！

7.2 方式二：教師手機 1 秒安全白名單認領 (/pair)

  • 使用方式：手機連線 Wi-Fi 後，在手機瀏覽器開啟：
    http://教師電腦IP:8000/pair
  • 資安防護設計：
    頁面會要求輸入教師管理 PIN 碼。輸入正確 PIN 碼後，系統會利用底層封包逆向捕捉該手機的真實 IP 與 MAC，自動將該裝置標籤升級為 【導師機】 並永久加入免斷網白名單，同時核發授權 Token，一鍵進入行動主控台！
    即使學生掃描或偷看該網址，沒有教師 PIN 碼也無法完成認領，徹底防止學生越權升級！

7.3 方式三：Android 原生 APK 直裝版下載與設定

為習慣安裝獨立 App 安裝包的老師提供了已編譯簽署的原生 APK：

  1. 取得 APK 安裝包與軟體檔案： - 官方 Google 雲端硬碟載點：可直接透過 Google 雲端硬碟官方下載連結 取得軟體安裝包與相關檔案。 - 手機直連下載：手機連上教室 Wi-Fi 後，掃描彈窗內的 APK 下載 QR Code，或直接在手機瀏覽器訪問 http://教師電腦IP:8000/download/apk。 - 電腦端傳送：由電腦端直接複製 dist/ClassNet_Sentinel_教師端.apk 安裝包至手機安裝（亦可自雲端硬碟下載後傳送）。
  2. 安裝與權限設定：點擊下載的 .apk 檔案，若系統提示「允許來自此來源的應用程式」，請勾選允許安裝。
  3. App 內建特色： - 打開 App 即自動載入教室主控台。 - 右上角提供 「⚙️ 主機設定」 按鈕，若教室主機更換或 IP 異動，隨時可一鍵輸入新 IP。 - 離線或 Wi-Fi 斷開時，介面會呈現友善的繁體中文引導與「🔄 重新連線」按鈕。

場景一：公開授課與視導觀摩 (Demonstration Teaching)

  • 教學情境：學校舉辦公開觀議課、校外專家視導或家長開放日。授課教師必須在 40 分鐘內流暢進行大螢幕電子白板講解、師生互動與學生平板答題，絕不容許網路延遲或學生在台下分心滑遊戲讓評委看見。
  • 標準實戰 SOP： 1. 課前 10 分鐘（白名單鎖定）：老師開啟班級網盾，點擊【真實掃描】，確認全班 30 台學生平板皆已在線，並點擊頂部【新裝置自動封鎖】（防止觀課家長或外人蹭網佔用頻寬）。 2. 教師講解階段（專注收心）：老師登台開場解說本節目標，手機輕點【開啟專注模式】，全班平板瞬間斷網，所有學生目光強制聚焦於大螢幕與黑板。 3. 互動答題階段（一秒還原）：進入分組答題時，老師手機點擊【解除專注模式】，全班平板秒級恢復網路連線，流暢進行互動測驗。 4. 觀摩成果：全程教學緊湊有序，完全杜絕學生偷玩載具引發觀課評委質疑的窘境。

場景二：標準化數位測驗與段考防作弊 (Online Examination)

  • 教學情境：全校進行英文聽力測驗、數位模擬考或線上期末考。學生使用平板登入校內測驗系統答題，為求公平，必須防範學生透過通訊軟體（LINE、Discord）互相通風報信或使用搜尋引擎查找答案。
  • 標準實戰 SOP： 1. 測驗前封閉通訊：利用班級網盾設定學生平板的上網排程，或在聽力講解階段維持全班專注模式斷網。 2. 測驗進行中（嚴密監控）：將儀表板切換至【事件時間軸】，隨時關注是否有學生嘗試利用私密隨機 MAC 開啟個人手機熱點蹭網。 3. 測驗鐘響結束（即時截斷）：測驗時間到，老師點擊【全班專注模式】，所有學生載具立即失去連線，無法再修改答案或傳送訊息，確保成績結算的公正客觀。

場景三：分組協作與平板數位專題 (Group Collaborative Learning)

  • 教學情境：自然科學或社會科專題探究課，學生進行 4 人一組分組討論，需要查閱網路文獻並製作簡報，但容易發生個別學生沉迷於觀看 YouTube 搞笑影片或打手遊的情形。
  • 標準實戰 SOP： 1. 分配課堂額度：老師針對各組平板，點擊【時限】按鈕，設定本節課「上網時限 35 分鐘」。 2. 巡堂動態激勵：老師拿著手機在教室巡堂走動。若發現第 2 組討論熱烈、進度超前，老師在手機端直接點擊【+15分鐘】給予該組網路額度獎勵！ 3. 超時自動收心：若第 4 組學生偷看非學習影片導致額度耗盡，系統自動阻斷其網路並註記「今日上網配額已用盡」，提醒該組學生專注於口頭討論與紙本整理。

場景四：午休自習與放學清場 (Study Hall & Sleep Routine)

  • 教學情境：中午 12:30 至 13:10 為全校午休睡眠時間，但常有住校生或留班學生在棉被底下偷滑平板、看小說；放學後亦有學生逗留在教室玩手遊不回家。
  • 標準實戰 SOP： 1. 設定定時排程：在各載具時限面板中，勾選「啟用定時斷網排程」，設定開始時間 12:30，結束時間 13:10。 2. 全自動執行：時間一到，系統後台守護進程自動切斷所有學生平板的 Wi-Fi 連線，時間結束自動恢復，教師無需手動守在電腦前。 3. 放學排程清場：另可設定每日 17:30 ~ 07:30 夜間斷網，徹底防範夜間偷連或校外人士夜間盜用校園 Wi-Fi。

場景五：校外教學與手機熱點露營 (Field Trips & Mobile Hotspot)

  • 教學情境：學校舉辦畢業旅行、戶外隔宿露營或童軍活動。晚間就寢後，學生常私自連線遊覽車或營區的 Wi-Fi 熬夜打線上遊戲，影響隔日行程體力與安全。
  • 標準實戰 SOP： 1. 隨身筆電監控：教師將裝有 ClassNet Sentinel 執行檔的輕薄筆電連入營區或民宿 Wi-Fi（亦支援教師手機開啟的行動熱點網段）。 2. 一鍵全網掃描：點擊【真實掃描】，瞬間收錄所有學生偷偷開機的手機與平板。 3. 就寢全面防護：就寢時間一到，老師啟動【新裝置自動封鎖】與【全體學生斷網】，夜間任何新開機的手機均無法連線，確保全班學生安心就寢。

場景六：校園私接 AP 與流氓基地台清查 (Rogue AP Hunting)

  • 教學情境：教室網路經常發生「整排電腦突然斷線」或「取得奇怪的 192.168.0.x IP」，資訊組懷疑有學生私自從家裡帶來小型無線路由器插在教室網路壁孔上，引發 DHCP 衝突。
  • 標準實戰 SOP： 1. 開啟診斷工具：切換至【專業網管工具】標籤頁。 2. 執行流氓 DHCP 探測：點擊【偵測私接 Rogue DHCP 分享器】按鈕。 3. 揪出元兇：系統發送廣播發現兩個不同的 DHCP 回應，並精確列出私接分享器的 MAC 位址與品牌（例如 TP-Link, 小米）。資訊組老師循線順利找出私接設備並拔除，瞬間恢復全班網路穩定。

場景七：課堂防窺雷達巡檢 (Privacy & Camera Sweep)

  • 教學情境：學校舞蹈教室、游泳池更衣室、會議室或校外住宿飯店，必須嚴防非法有心人士安裝隱蔽式 Wi-Fi 針孔攝影機偷拍。
  • 標準實戰 SOP： 1. 入住或使用前檢驗：將筆電連上該環境之 Wi-Fi 網路。 2. 啟動視訊協定雷達：切換至【安全漏洞掃描】標籤頁，點擊【即時偵測】針孔防窺雷達。 3. 自動全網檢驗：系統在 1 秒內檢測網段內所有設備是否開放 RTSP 554 即時視訊串流或 ONVIF 3702 監視協定。 4. 無死角守護：若結果顯示「未發現可疑攝影機」，即可向師生宣布環境安全，全力保障個人隱私尊嚴。

九、常見問題與疑難排解 (FAQ)

Q1：為什麼點擊【一鍵斷網】後，部分設備依然能上網？

  • 解答：
    Windows 系統底層若未安裝封包擷取驅動，系統只能以常規 Socket 嘗試發送 TCP Reset 控制訊號。為達到 100% 完美的阻斷效果，強烈建議安裝 Npcap 驅動程式（微軟數位簽名、WinPcap 現代相容升級版）。
  • 若主控台頂部出現黃色提示「⚠️ 尚未檢測到 Npcap 核心驅動」，請直接點擊提示列中的連結下載安裝。
  • 安裝時請務必勾選 「Install Npcap in WinPcap API-compatible Mode」。安裝完成後重新啟動主控台，斷網阻斷即可達 100% 強制壓制效果。

Q2：學生知道老師電腦的 IP，會不會自己開啟瀏覽器登入系統給同學斷網？

  • 解答：
    絕對不可能！
  • ClassNet Sentinel 具備本機特許與外網嚴格鎖定機制。
  • 任何外部 Wi-Fi 設備存取主機 IP 時，畫面會強制彈出全螢幕 PIN 碼鎖定遮罩，未輸入正確教師管理密碼前無法看見任何資料。
  • 若嘗試透過命令調用後端 API，一律被 403 Forbidden 攔截並在事件時間軸留下警告稽核紀錄。

Q3：忘記教師管理 PIN 碼該怎麼辦？

  • 解答：
    只要回到講台本機電腦前操作即可！
    因為講台電腦為本機連線（127.0.0.1），享有實體在場免密特許權。老師只要坐在電腦前，點擊頂部的「🔑 鑰匙圖示」，即可直接設定一組全新的 PIN 碼，完全不用擔心被鎖在門外。

Q4：學生的 iPhone / Android 平板每次重連 MAC 位址都不一樣，如何管理？

  • 解答：
    這是行動裝置預設啟用的「私密 Wi-Fi 位址」功能。
  • 本系統會自動辨識並標記紫色 【私密MAC】。
  • 老師可請學生在平板的 Wi-Fi 設定中，將教室 Wi-Fi 的「專用位址 / 隨機 MAC」切換為「使用裝置 MAC」，即可永久固定實體 MAC 位址，方便精準命名為「第 1 組平板」、「第 2 組平板」。

Q5：路由器弱點檢查中 Port 53 (DNS) 與 Port 443 (HTTPS) 開放是否正常？

  • 解答：
    這是完全正常的！
  • Port 53 (DNS) 是路由器為全班電腦解析網址必備的服務。
  • Port 443 (HTTPS) 是路由器原廠的加密安全 Web 管理介面。
  • 只要 Port 23 (Telnet) 與 Port 7547 (TR-069) 呈現綠色「安全關閉」，您的教室路由器即具備優良的抗滲透安全強度。
