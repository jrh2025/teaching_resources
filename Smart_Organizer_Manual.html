Smart Organizer 設計理念與使用說明手冊

0. 程式下載位置與首次開啟指引

本程式為單檔免安裝版，解壓縮後雙擊 smart-organizer.exe 即可使用，不寫入系統機碼、不需安裝任何額外執行環境。

📦 官方雲端下載位置（Windows 64-bit 壓縮包）： https://drive.google.com/file/d/1ODyRgSzEW__rpcViSBgmKYWvEV_QNori/view?usp=sharing

下載並解壓縮

設計理念

1. 核心設計哲學：為什麼這樣設計？

多數檔案整理工具容易陷入兩個極端：要麼只看副檔名粗暴搬移（導致整個程式專案被拆得支離破碎），要麼沒有預覽與反悔機制，整理一次反而更找不到東西。Smart Organizer 在設計上堅持四大核心支柱：

🛡 1. 安全永遠優先於自動化

絕不未經確認就靜默刪除資料。重複檔與無用檔優先集中至 05_待確認隔離區；所有搬移與原地取代皆寫入獨立時間戳 JSONL 復原日誌，隨時可一鍵還原。

🧩 2. 語意邊界感知，而非只看副檔名

同時讀取檔案前 8KB 的 Magic Bytes 真實格式、照片 EXIF 拍攝日期，並辨識專案根目錄標記。副檔名被改錯的檔案也能正確歸類，專案資料夾更會被完整保留。

👁 3. 預覽即所得（WYSIWYG）

掃描完成後，目標路徑撞名消歧（如 (1)）、同名專案區別、AI 更名與手動調整分類都會在列表即時定案；「整理前後規劃總覽」更讓您先看藍圖再動手。

⚡ 4. 極致效能與隱私主權

單次平行遍歷（不重覆掃描快取或子目錄），配合虛擬捲動渲染萬級檔案。AI 功能預設完全關閉，僅在您自行填入 API Key 或連接本地 Ollama 時啟用，金鑰預設不寫入硬碟。

系統架構

2. 系統架構與多階段處理管線

為了兼顧掃描速度與分類準確度，Smart Organizer 採用「單次 I/O 掃描 → 無用檔預檢 → 三段式去重 → 規則分類 → 預覽消歧 →（選配）AI 語意歸納 → 安全執行」七段流水線，耗時作業全部在背景執行緒執行，不阻塞桌面視窗操作。

模組檔案 職責定位 關鍵設計亮點
scanner.rs 單次平行掃描與邊界偵測 不重複遍歷計算大小、忽略內部標記與復原日誌、不跟隨符號連結、自動區分同名專案。
dedup.rs 三段式 BLAKE3 去重引擎 只對有效非隔離檔案比對，避開 0-byte 與垃圾檔干擾；rayon 平行讀寫與計算。
classifier.rs 規則與 EXIF 智慧分類 捷徑辨識、截圖獨立分箱、Magic Bytes 真實格式偵測、當地時區日期回退、預覽撞名消歧。
executor.rs 執行、復原與強制清理 原地整理與空目錄安全清理、跨磁碟目錄複製校驗、獨立復原日誌、解除唯讀與長路徑強制刪除。
ai.rs 選配雲端／本地 AI 引擎 Gemini 與 OpenAI-compatible 雙支援、純文字自動過濾、嚴格消毒路徑與 Windows 保留字。
config.rs & app.rs 設定持久化與互動介面 自動偵測桌面/下載/文件位置、虛擬捲動列表、即時進度條與中途取消、Before→After 規劃總覽。
專案保護機制

3. 複雜多層專案與檔案安全防護

程式開發專案、Unity/Unreal 遊戲專案或複合設計專案往往包含數十層子資料夾與圖片、PDF、字型、二進位檔等多種格式。一般整理工具很容易誤把專案裡的貼圖抽進「照片區」、說明書抽進「文件區」，導致專案編譯失敗。

Smart Organizer 的四重專案安全防線

  • 廣泛的專案根目錄標記辨識： 自動偵測 .git、.hg、.svn、Cargo.toml、package.json、pyproject.toml、go.mod、pom.xml、build.gradle(.kts)、settings.gradle(.kts)、composer.json、CMakeLists.txt、pubspec.yaml、Gemfile、mix.exs、Makefile、meson.build、Unity ProjectSettings，以及 .sln、.csproj、.vbproj、.vcxproj、.xcodeproj、.xcworkspace。
  • 單一原子單元保護（Atomic Unit）： 一旦目錄被判定為最外層專案（top_projects），其內部所有子模組、靜態資源、文件與設定檔一律封存於專案內整體移動，不進入去重也不拆散分類，列表中以 🛡 完整專案（原子保護） 標示並鎖定不可誤改分類。
  • 排除內部偽標記誤判： 不會把 node_modules、target、.venv 或已整理好的非專案分類夾裡的 package.json 誤認為獨立專案；不同子目錄下的同名專案（如 work/app 與 personal/app）會自動補上父目錄區分命名。
  • 跨磁碟複製完整性校驗與來源警示： 若跨磁碟機搬移專案（無法單純透過 rename 完成），系統會先遞迴複製並核對檔案總數與總位元組數完全一致後才安全移除來源；若使用者不小心選取了本身即專案根目錄的資料夾作為來源，頂部會立即顯示橘色安全警告。
去重演算法

4. 為什麼「先預檢垃圾，再去重」？

許多資料夾中存在複數個 Thumbs.db、.DS_Store 或相同的 0-byte 空檔案。如果先做去重，系統會誤把其中一個 Thumbs.db 視為「主檔」，另一個標記為「重複檔」，導致重複空間統計失真。

1
階段 A：無用垃圾預檢（Pre-diagnosis）

先挑出 0-byte 空檔、系統殘留（.DS_Store、Thumbs.db、desktop.ini、._*）與未完成下載（.crdownload、.part、.tmp、.download），直接歸入隔離區。

2
階段 B：大小分組 → 頭中尾 4KB 局部雜湊 → 完整 BLAKE3

只對「非專案、非隔離區、大小 > 0」的有效檔案執行。先依檔案大小過濾唯一值，再平行讀取頭、中、尾各 4KB 計算局部雜湊，最後只對依然碰撞的極少數候選者計算完整 BLAKE3，大幅節省磁碟讀取時間。

3
階段 C：保留主檔與標註建議

每組重複檔中保留「修改時間較早（若相同則路徑較短）」的檔案為主檔留在原分類；其餘重複副本歸入 05_待確認隔離區/重複檔案 並附註來源主檔名稱與「建議刪除」提示。

使用手冊 · 最受歡迎情境

5. 凌亂桌面一鍵整理實戰教學

打開 smart-organizer.exe 後，不需手動翻找使用者目錄，頂部的「🖥 懶人快速規劃」提供專為桌面設計的雙方案：

方案 A：✨ 載入桌面（原地精簡分類） 自動偵測系統桌面（含 Windows OneDrive 桌面），切換為原地整理並開啟「保留桌面捷徑於原位」與「截圖獨立分箱」。整理後，您的桌面只會留下常用軟體捷徑＋數個整齊分類箱，並自動移除被搬空的舊資料夾。
方案 B：🧹 桌面極淨歸檔（移至「文件」資料夾） 適合追求「零雜物極簡桌面」的使用者！保留常用的軟體與網頁捷徑留在桌面上方便點擊，把散落桌面各處的 PDF、簡報、照片、截圖與壓縮包一次搬移歸檔至 文件/桌面整理歸檔_YYYYMMDD（含完整復原日誌）。

標準四步驟操作流程

1
一鍵載入與自動掃描

點擊「✨ 載入桌面（原地精簡分類）」或「🧹 桌面極淨歸檔」（或手動選取任意來源資料夾並按「🔍 1. 快速掃描與診斷」）。系統會自動識別捷徑、專案、截圖、文件與重複垃圾。

2
先清垃圾：一鍵處理「智慧清理建議」

若掃描發現重複檔、空檔、系統殘留或陳舊安裝檔，列表上方會亮起「🧹 智慧清理建議」列，顯示可釋放總空間。點擊「🗑 一鍵移至回收桶」即可先瘦身（遇到唯讀檔刪不掉時系統會主動引導轉用強制刪除）。

3
開啟「🗺 整理前後規劃總覽 (Before → After)」確認藍圖

檢視整理前後的對比結構、保留原位捷徑數量、各分類資料夾項目數與大小；若有個別檔案想改分類，直接在列表中下拉調整即可。還可點「📋 複製規劃報告 (Markdown)」留存紀錄。

4
確認執行，隨時可一鍵復原

點擊「🚀 執行整理」或「🚀 執行原地取代」，執行進度條會即時回報進度（也可隨時按「⏹ 取消」中斷）。完成後若不滿意，按「↩ 一鍵復原上次搬移」即可還原。

桌面三大貼心預設保護 1. 工具列預設勾選「保留桌面捷徑於原位」，Chrome、Line、Office 等 .lnk / .url 圖示不會被收進資料夾。
2. 桌面根目錄下的系統隱藏檔 desktop.ini 預設略過保護，不影響 Windows 圖示排版與資料夾名稱顯示。
3. 檔名含 螢幕擷取、截圖、Screenshot、Snipaste 等截圖圖片會自動獨立歸入 螢幕截圖/YYYY-MM，不與旅遊照片混雜。
使用手冊 · 執行模式

6. 三種執行模式與復原機制

模式名稱 對原目錄的影響 安全防呆與日誌 適用情境
安全複製（保留原檔） 來源資料夾完全不動，在目標資料夾建立整理好的副本。 禁止來源與目標路徑重疊或互相包含；預覽即消歧。 第一次使用、想先在旁測試分類成果或保留原貌備份。
搬移至目標（含獨立復原日誌） 將勾選項目從來源搬移至全新的目標資料夾（同磁碟秒速搬移）。 寫入 .organizer_undo_YYYYMMDD_HHMMSS.jsonl 獨立日誌。 「桌面極淨歸檔」或將下載區彙整到外部硬碟／文件歸檔區。
原地整理（直接取代原目錄） 直接在來源資料夾內重新歸類成整齊子目錄，並可自動清理搬空的舊子目錄。 寫入獨立復原日誌；自動跳過已位於正確目標的檔案與日誌檔本身。 「桌面原地精簡」、直接整理現有混亂資料夾且不想多出新位置。

如何進行復原（Undo）？

  • 當次立即復原：搬移或原地整理完成後，頂部會出現「↩ 一鍵復原上次搬移」按鈕，點擊後於背景執行緒倒序還原所有項目（且不會覆蓋任何新增的同名檔案）。
  • 重開程式後復原過去紀錄：點擊右上角「📂 選擇日誌復原」，選取目標（或原）資料夾內隱藏的 .organizer_undo_*.jsonl 檔案即可還原。當整份日誌完全還原成功後，系統會自動將其更名為 *.restored.jsonl 避免重複執行。
使用手冊 · 深度清理

7. 智慧清理建議、快取清理與強制移除

針對一般使用者最頭痛的「重複檔佔空間」與「部分檔案或資料夾死活刪不掉（例如含唯讀 .git 或超長路徑 node_modules）」問題，系統提供兩階段安全清理能力：

🗑 一般清理：移至系統資源回收桶

適用所有常規重複檔、0-byte 空檔、系統殘留、過期安裝包與肥大快取。刪除後仍可在 Windows 資源回收桶／macOS 垃圾桶找回。若發生部分檔案因唯讀或路徑過長無法移入回收桶，系統會自動彙整失敗清單，彈出視窗詢問是否改用「強制永久刪除」。

⚡ 強制移除：強制永久刪除

點擊前必經紅色警告二次確認視窗（標示影響數量與總空間）。執行時自動解除唯讀屬性（readonly）、支援 Windows \\?\ 長路徑延伸前綴、針對短暫占用重試，且嚴格不跟隨符號連結誤刪外部目錄。

如何清理開發專案留下的肥大快取？ 掃描後若偵測到大於門檻（預設 10 MB）的 node_modules、target、__pycache__、.venv、.next、dist，列表上方會顯示黃色提示條與「檢視／清理快取目錄」按鈕，點開後可依大小排序勾選並自由選擇「移至回收桶」或「強制永久刪除」。

進階設定與隱私

9. 選配 AI 語意歸納與分類規則設定

點擊視窗右上角「⚙ 設定（AI 與分類規則）」即可切換兩大設定分頁，所有設定會自動儲存至本機設定檔：

  • Windows 設定檔位置：%APPDATA%\SmartOrganizer\settings.json
  • macOS 設定檔位置：~/Library/Application Support/SmartOrganizer/settings.json
  • Linux 設定檔位置：~/.config/smart-organizer/settings.json
🤖 AI 輔助設定（預設關閉）

疑難排解

10. 常見問題與安全排解 (FAQ)

Q1：桌面整理後，我常用的 Chrome / Line / Office 圖示會不會不見？

不會。只要工具列上的「保留桌面捷徑於原位」保持勾選（預設開啟），所有 .lnk、.url 等桌面捷徑都會自動取消勾選搬移，穩穩留在原本的桌面位置。如果未來您希望連捷徑一起收進 00_常用捷徑，取消該勾選即可即時生效。

Q2：為什麼有些資料夾明明有許多檔案，Smart Organizer 卻把它當作「一個項目」整體搬移？

那是專案邊界保護機制在運作。只要該資料夾內含有 .git、package.json、Cargo.toml、pyproject.toml、.sln 等開發標記，程式就會判定它是一個完整專案，為了確保不拆散原始碼與資源檔案導致無法編譯或執行，會以單一原子單位整體處理。

Q3：在「原地整理」模式下，如果我整理完之後過幾天桌面又亂了，可以再整理一次嗎？

可以。再次點擊「✨ 載入桌面（原地精簡分類）」掃描時，程式會自動忽略內部的 .organizer_undo_*.jsonl 日誌檔，也不會把已整理在 03_教學教材與文件 裡的散落設定檔誤認為程式專案；已位於正確目標路徑的檔案與專案也會安全略過，只會把新出現的雜亂檔案歸入對應分類箱。

Q4：按下「一鍵移至回收桶」時跳出「有部分項目無法移除」怎麼辦？

這通常發生在含有唯讀屬性的檔案（例如舊專案殘留的 .git 物件）、路徑長度超過 Windows 260 字元限制的深層 node_modules，或系統特殊屬性暫存檔。此時程式會自動跳出提示視窗詢問您是否對這批失敗項目改用「⚡ 強制永久刪除」——確認後系統會解除唯讀並透過延伸長路徑移除。若仍失敗，代表該檔案正被其他開啟中的程式鎖定，請先關閉相關程式後再試。

Q5：執行到一半突然想停止，或整理完後悔了怎麼辦？

執行中可隨時點擊底部進度條旁的「⏹ 取消」，程式會立即安全中止後續項目，並為「已完成搬移」的項目保留合法的復原日誌。完成或取消後，只要點擊「↩ 一鍵復原上次搬移」（或「📂 選擇日誌復原」選取對應的 .organizer_undo_*.jsonl），即可把已搬移的檔案全部還原回原路徑。
